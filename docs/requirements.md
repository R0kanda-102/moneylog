# 머니로그(MoneyLog) 요구사항 정의서

- 작성자: 김태영
- 작성일: 2026-07-23
- 프로젝트 기간: 5일

## 1. 프로젝트 개요

- 한 줄 소개: 개인이 수입/지출을 기록하고 카테고리별·월별 통계를 보는 가계부 웹 서비스
- 대상 사용자: 로그인한 개인 사용자(내 데이터는 나만 접근)
- 목표: 부트캠프 전 과정(자바/스프링/JPA/시큐리티/프론트/DevOps) 복습 + AWS EC2 실배포까지 완주

## 2. 유저 스토리

|---|-----------------------------------------------|
| US-1 | 사용자로서 나는 이메일과 비밀번호로 회원가입/로그인하고 싶다, 왜냐하면 내 가계부를 나만 보고 싶기 때문이다. |
| US-2 | 사용자로서 나는 수입과 지출을 등록하고 싶다, 왜냐하면 돈이 어디서 들어오고 나가는지 기록해야 하기 때문이다. |
| US-3 | 사용자로서 나는 등록한 거래를 수정·삭제하고 싶다, 왜냐하면 금액이나 날짜를 잘못 입력할 수 있기 때문이다. |
| US-4 | 사용자로서 나는 거래를 식비·교통 같은 카테고리로 분류하고 싶다, 왜냐하면 어디에 돈을 많이 쓰는지 알고 싶기 때문이다. |
| US-5 | 사용자로서 나는 이번 달 거래를 카테고리·타입으로 걸러서 보고 싶다, 왜냐하면 원하는 항목만 빠르게 확인하고 싶기 때문이다. |
| US-6 | 사용자로서 나는 이번 달 총수입·총지출·잔액과 카테고리별 지출을 보고 싶다, 왜냐하면 한 달 예산 상태를 한눈에 파악하고 싶기 때문이다. |
| US-7 | 사용자로서 나는 내 데이터에만 접근하고 싶다, 왜냐하면 남이 내 가계부를 보거나 고치면 안 되기 때문이다. |
| US-8 | (도전) 사용자로서 나는 카테고리별 월 예산을 정하고 초과 시 경고를 받고 싶다, 왜냐하면 과소비를 막고 싶기 때문이다. |

> US-8은 "왜냐하면"이 명확하지만 5일 일정상 여유가 없으면 도전(Could)으로 미룬다.

## 3. 기능 요구사항 (MoSCoW)

| ID | 기능 | 설명 | 우선순위(Must/Should/Could) |
|----|------|------|:---:|
| F-01 | 회원가입/로그인 | JWT 발급, BCrypt | Must |
| F-02 | 카테고리 관리 | 시드 + CRUD | Must |
| F-03 | 거래내역 CRUD | 수입/지출 등록·조회·수정·삭제 | Must |
| F-04 | 목록 필터·페이징 | yearMonth/type/categoryId + page/size | Must (필터 조합은 Should) |
| F-05 | 월별 통계 | 총수입·지출·잔액, 카테고리별 지출 | Must (카테고리별 집계는 Should) |
| F-06 | 인가 | 본인 데이터만 | Must |
| F-07 | 검증·예외 | 금액>0, 날짜 필수, {success:false, code, message, data:null} | Must (전역 예외 봉투 통일은 Should) |
| F-08 | 프론트 필수 2종 | 로그인, 목록+등록 (통계는 여유 시) | Must |
| F-09 | Swagger | API 문서화 | Should |
| F-10 | 배포 | Docker+GitHub Actions+EC2 | Must |
| F-11 | 월 예산·초과 경고 | Budget 엔티티 | Could (도전) |
| F-12 | 통계 시각화 | 파이/라인 차트 | Could (도전) |
| F-13 | 검색·CSV 내보내기 | 키워드/기간/금액범위, CSV | Could (도전) |

## 4. 비기능 요구사항

| 분류 | 요구사항 | 구체적 기준 |
|------|----------|-------------|
| 보안 | 본인 데이터만 | 모든 조회/수정/삭제는 user_id 기준 필터, 남의 리소스는 403 |
| 보안 | 비밀번호 | 평문 저장 금지, BCrypt 해시로 저장 |
| 보안 | 인증 방식 | Authorization: Bearer {accessToken} (JWT) |
| 성능 | 목록 조회 | page/size 페이징, 전체 로딩 금지 |
| 성능 | 통계 응답 | DB 집계 쿼리(SUM/GROUP BY)로 계산 |
| 검증 | 입력 유효성 | amount > 0, transactionDate 필수, type은 INCOME/EXPENSE만 |
| 품질 | 에러 응답 | {success:false, code, message, data:null} 형태로 통일 |
| 배포 | 실접속 | AWS EC2에 배포되어 실제 접속 가능한 URL 제공 |
| 문서 | API 문서화 | Swagger UI로 API 명세 확인 가능 |

## 5. 범위(Scope)

| 구분 | 내용 |
|------|------|
| 기본 과제 (In Scope) | 이메일 회원가입/로그인(JWT), 카테고리 시드+CRUD, 거래 CRUD, 월별 필터, 이번 달 총수입/지출/잔액, 본인 데이터 인가, 기본 입력 검증, 로그인·목록+등록 화면, Docker+GitHub Actions+EC2 배포 |
| 도전 과제 (Stretch) | 카테고리별 지출 집계, 목록 타입/카테고리 필터 조합, 월 예산+초과 경고, CSV 내보내기 |
| 이번엔 안 함 (Out of Scope) | 이메일 인증, 비밀번호 찾기, 소셜 로그인, Refresh Token, 반복 거래, 영수증 첨부, K8s/Jenkins, 성능 부하 테스트 |
